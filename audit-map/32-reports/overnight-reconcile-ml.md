## v7 Overload Diagnosis

Canonical headline: v7 Overload = **1.1127** (`audit-map/20-prompts/fresh-sem1-principal-architect-overnight-pass.md:398`), exceeding the 1.00 guardrail (`audit-map/14-reconciliation/final-decision-appendix.md:136`). Three ranked candidate causes:

- **#1 (root) — Missingness signal suppression by 0.5 imputation.** v7 feature pipeline imputes unknown `currentCgpa` / `backlogCount` as 0.5 sentinel, which the logistic model cannot distinguish from "worst-case CGPA / zero backlog". The fix is encoded in-repo as `CORRECTED_V8_PROOF_RISK_TRAINING_CONFIG`, adding binary `cgpaMissingScaled` and `backlogMissingScaled` features to restore the missingness signal (`air-mentor-api/src/lib/proof-risk-model.ts:62-63`, `air-mentor-api/src/lib/proof-risk-model.ts:118-119`, `air-mentor-api/src/lib/proof-risk-model.ts:120-129`). Rationale: the hybrid model (logistic+challenger blend) also shows Overload 1.1127 (`audit-map/20-prompts/fresh-sem1-principal-architect-overnight-pass.md:399`), so blending cannot rescue it; the defect is in the feature vector upstream of the head, not in calibration or head selection.
- **#2 Stage concentration at `post-see`.** Stage-specific overload ratio is materially higher than the global headline (1.3738 vs 1.0683) in the current evaluation artifact slices, indicating that late-stage student distributions dominate budget-rate overflow (`air-mentor-api/output/proof-risk-model/evaluation-report.json:58770`, `air-mentor-api/output/proof-risk-model/evaluation-report.json:58934`, `air-mentor-api/output/proof-risk-model/evaluation-report.json:58939`). Fix cost-share cannot be assigned to v8 feature work alone; stage-conditional thresholds remain necessary.
- **#3 Capacity-policy coupling under faculty overload penalties.** Even with model scoring corrected, runtime budget clamps for Course Leader / Mentor / HoD roles tighten effective throughput when faculty weekly contact hours exceed threshold, so a fixed global budget-rate of 0.2 cannot be read purely as a model metric (`air-mentor-api/src/lib/proof-control-plane-runtime-service.ts:355`, `air-mentor-api/src/lib/proof-control-plane-runtime-service.ts:357`, `air-mentor-api/src/lib/proof-control-plane-runtime-service.ts:377`). Fix requires monitoring-layer split: report model overload and capacity-policy clamp separately.

Promotability decision is already encoded in the prompt (`audit-map/20-prompts/fresh-sem1-principal-architect-overnight-pass.md:404-409`): do not promote v7 unchanged; hybrid does not rescue overload; depth-2 tree challenger is not promotable; heuristic remains worse as a general predictor. Path forward is `CORRECTED_V8_PROOF_RISK_TRAINING_CONFIG` with world-semantics and stage/date authority fixed first.
