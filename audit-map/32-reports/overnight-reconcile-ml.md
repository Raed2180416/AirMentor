## Findings
- Model层今实为“五头先行，band 后映”：`RiskHeadKey` 明定五头；`scoreObservableRiskWithModel` 先算五头，再以 `overallCourseRisk` 过 `0.4/0.85` 阈生成 `riskBand` (`air-mentor-api/src/lib/proof-risk-model.ts:16-19`, `air-mentor-api/src/lib/proof-risk-model.ts:78-83`, `air-mentor-api/src/lib/proof-risk-model.ts:2063-2075`).
- Policy层今为 rule/explainer + acceptance-gate 层，非 model scorer：`inferObservableDrivers` / `inferObservableRisk` 读 policy rule 出 explainers；`buildPolicyDiagnostics` 另定义 same-checkpoint counterfactual wording 与 support gate (`air-mentor-api/src/lib/inference-engine.ts:36-39`, `air-mentor-api/src/lib/inference-engine.ts:172-186`, `air-mentor-api/src/lib/proof-control-plane-policy-service.ts:386-406`).

## v7 Overload Diagnosis
`overloadRatio = flaggedRateAtBudget / budgetRate`。是故 baseline `1.0` 仅表“正等预算”；源码注释保留 v7 headline `1.1127`，即高于预算中性线 (`air-mentor-api/scripts/evaluate-proof-risk-model.ts:523-550`, `air-mentor-api/src/lib/proof-risk-model.ts:118-119`).

候因排序如下：

1. 首因候选：missingness signal surface 已写，caller 未接。feature schema 增 `cgpaMissingScaled` / `backlogMissingScaled` 且注释直指“Fixes v7 overload=1.1127”；然 playback/runtime/academic build path 皆未传 missingness flags。此意味着“修复意图”与“现行 authority”分离，最可疑 (`air-mentor-api/src/lib/proof-risk-model.ts:61-63`, `air-mentor-api/src/lib/proof-risk-model.ts:118-129`, `air-mentor-api/src/lib/proof-control-plane-playback-governance-service.ts:222-243`, `air-mentor-api/src/lib/proof-control-plane-runtime-service.ts:548-566`, `air-mentor-api/src/modules/academic.ts:1424-1445`).
2. 次因候选：stage-conditioned overload 偏聚后段。活跃 artifact 中 overall slice 为 `1.0683`，而 `post-see` slice 升至 `1.3738`，`post-assignments` 亦达 `1.2951`；故单一全局阈/单一 headline 易掩 stage skew (`air-mentor-api/output/proof-risk-model/evaluation-report.json:58769-58775`, `air-mentor-api/output/proof-risk-model/evaluation-report.json:58801-58808`, `air-mentor-api/output/proof-risk-model/evaluation-report.json:58933-58939`).
3. 三因候选：capacity-policy clamp 混入 overload 叙事。runtime 先算 faculty overload penalty，再 clamp Course Leader / Mentor / HoD budget；若报表不拆“model overload”与“capacity clamp overload”，则会把运营容量惩罚误读为纯模型缺陷 (`air-mentor-api/src/lib/proof-control-plane-runtime-service.ts:352-379`).
4. 辅因候选：calibration family 并非根因救星。code 允许 `beta`，然活跃 artifact 现见 `isotonic`；在 missingness/capacity/stage skew 未拆前，单换 calibrator 难独救 overload (`air-mentor-api/src/lib/proof-risk-model.ts:919-1040`, `air-mentor-api/output/proof-risk-model/evaluation-report.json:9117-9123`).

结论：v7 overload 不宜写作“单点校准故障”。较稳表述应为“feature missingness authority 未贯通 + stage skew + capacity clamp 混叠”之复合症候。
